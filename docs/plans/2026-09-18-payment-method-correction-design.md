---

## 1. 問題描述

社區管理費收繳系統上線後，實際作業中出現三個缺口：

1. **收款送出後無法更正付款方式**。財委在收款視窗按下「確認收款」後才發現現金／轉帳選錯，系統目前沒有任何修改入口（`PUT /api/payments/[id]` 有 API，但 UI 沒有入口）。
2. **簽收單缺少轉帳明細**。交付流程只處理現金（`paymentMethod = 'cash'`），轉帳記錄從來不會綁定 `handoverId`，因此簽收單上完全看不到同期的轉帳收款。
3. **轉帳記錄的狀態顯示錯誤**。轉帳的 `handoverStatus` 永遠停在 `pending`，報表中心顯示為「待交付」，會讓人誤以為那筆錢還在財委手上。

---

## 2. 需求

1. 收款送出後可更正付款方式（現金 ↔ 轉帳）
2. 更正只變動付款方式一個欄位，其餘欄位（金額、收據編號、收據照片、收款日期、備註、期別）完全不動
3. 已被歸到某張簽收單的記錄鎖住，不可更正
4. 更正入口設於兩處：收款作業頁、報表中心收款明細
5. 交付時，將尚未被任何簽收單收錄的轉帳記錄一併歸戶到該張簽收單
6. 既有簽收單依付款日期做一次性回填，重印時即可看到轉帳明細
7. 簽收單新增「轉帳明細（非現金）」區塊，有自己的小計
8. 轉帳金額不計入交付總金額，摘要區另加一行標示
9. 付款方式為轉帳的記錄，狀態一律顯示「已轉帳」
10. 臨時收費（`adhocPayments`）比照辦理：同樣可更正付款方式、同樣納入簽收單轉帳明細、同樣顯示「已轉帳」

---

## 3. 已定案決策

| # | 決策點 | 結論 |
|---|--------|------|
| 1 | 修正範圍 | 已交付的記錄鎖住；更正只動付款方式一欄，其他欄位不碰 |
| 2 | 轉帳歸戶 | 交付時把尚未被任何簽收單收錄的轉帳一併掛上；舊簽收單依付款日期一次性回填 |
| 3 | 狀態顯示 | 只要付款方式是轉帳，一律顯示「已轉帳」（簽收單、報表中心、Excel 一致） |
| 4 | 修正入口 | 收款作業頁 + 報表中心收款明細，兩處共用同一個更正視窗 |
| 5 | 已交付例外 | 鎖住並顯示交付日期與簽收單編號，不開後門（不設管理員強制修改） |
| 6 | 簽收單金額 | 轉帳獨立一段、有自己的小計，不計入交付總金額 |
| 7 | 臨時收費 | 比照管理費辦理，三項需求全部適用於 `adhocPayments` |

## 4. 更正付款方式 — 行為規格（已確認）

### 判斷可否更正

以 `payments.handoverId` 是否為 `NULL` 作為唯一判準，比 `handoverStatus` 更準確：

- `handoverId IS NULL` → 可更正
- `handoverId` 有值 → 鎖住（現金與已歸戶的轉帳一視同仁）

### 手持現金的連動

不需要任何補帳邏輯。`/api/cash/balance` 是即時 SUM 查詢（`handoverStatus = 'pending' AND paymentMethod = 'cash'`），更正後餘額自動反映：

- 現金 → 轉帳：手持現金減少該筆金額
- 轉帳 → 現金：手持現金增加該筆金額

### 使用者流程

```
收款作業頁                        報表中心 → 收款明細
點綠色已繳格子                     點該列的鉛筆鈕
      │                                  │
      └──────────────┬───────────────────┘
                     ↓
          ┌──────────────────────┐
          │  讀取該筆繳費記錄     │
          └──────────┬───────────┘
                     ↓
            handoverId 是否為 NULL？
                     │
        ┌────────────┴────────────┐
       是                         否
        ↓                          ↓
  下拉可選，可儲存          欄位灰掉，顯示鎖定原因
        ↓                          ↓
  PATCH 只更新               只能關閉視窗
  paymentMethod
        ↓
  重新載入清單與餘額
```

### 對既有行為的影響

收款作業頁點綠色格子，目前的行為是跳出 toast「已繳費」，將改為開啟此更正視窗。

### 臨時收費一併適用

`adhocPayments` 與 `payments` 的結構相同（都有 `paymentMethod`、`handoverStatus`、`handoverId`），三項需求全部比照辦理：

| 面向 | 管理費 `payments` | 臨時收費 `adhocPayments` |
|------|------------------|------------------------|
| 更正付款方式 | ✓ | ✓ 同規則，`handoverId IS NULL` 才可改 |
| 交付時歸戶轉帳 | ✓ | ✓ 一併掛上同一張簽收單 |
| 舊簽收單回填 | ✓ | ✓ 同一套日期規則 |
| 簽收單轉帳明細 | ✓ | ✓ 併入同一個「轉帳明細（非現金）」區塊，以來源欄區分 |
| 狀態顯示「已轉帳」 | ✓ | ✓ |

手持現金的連動同樣自動成立：[`/api/cash/balance`](../../src/app/api/cash/balance/route.ts) 已經分別統計 `payments` 與 `adhocPayments` 的待交付現金，更正後兩邊都會即時反映。

## 5. 待確認事項

以下尚未與使用者討論，實作前需先確認：

### 第 2 節 — 簽收單版面與回填規則

- 舊簽收單回填的日期歸戶規則（初步構想：一筆轉帳歸到「`handoverDate >= 該筆 paymentDate` 的最早一張簽收單」；落在最後一張簽收單之後的維持未歸戶，等下次交付時處理）
- 轉帳明細區塊在簽收單上的實際版面位置與欄位
- 摘要區「同期轉帳 $X（未含在交付現金內）」的文字與位置
- 簽收單轉帳明細區塊中，管理費與臨時收費的呈現方式（合併為一張表加來源欄，或各自分表）

### 第 3 節 — 技術實作與檔案清單

- 更正用的 API 端點形式（新增專用 PATCH，或沿用現有 PUT）；臨時收費需新增對應端點，目前 `adhocPayments` 沒有單筆更新 API
- 臨時收費的更正入口位置。[adhoc/page.tsx](../../src/app/adhoc/page.tsx) 目前只有格狀勾選、沒有已繳清單，已繳的格子是不可點狀態；初步構想是比照收款作業頁，點已繳格子開啟更正視窗
- 報表中心收款明細目前只顯示管理費，不含臨時收費，是否要一併納入
- 既有 `PUT /api/payments/[id]` 使用 `.set({ ...body, totalAmount })` 直接展開 request body 寫入，範圍過寬，需一併處理
- 舊簽收單回填的執行方式（一次性 script 或 migration）
- 修改檔案清單與驗收標準

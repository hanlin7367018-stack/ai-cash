---

## 1. 問題描述

社區管理費收繳系統上線後，實際作業出現三個缺口：

1. **收款送出後無法更正付款方式**。財委按下「確認收款」後才發現現金／轉帳選錯，UI 沒有任何修改入口。
2. **簽收單缺少轉帳明細**。交付流程只處理現金，轉帳記錄從不綁定 `handoverId`，簽收單上看不到同期轉帳收款。
3. **轉帳記錄狀態顯示錯誤**。轉帳的 `handoverStatus` 永遠停在 `pending`，報表中心顯示「待交付」，使人誤以為錢還在財委手上。

---

## 2. 需求

1. 收款送出後可更正付款方式（現金 ↔ 轉帳）
2. 更正只變動付款方式一個欄位，其餘欄位完全不動
3. 已被歸到某張簽收單的記錄鎖住，不可更正
4. 更正入口設於收款作業頁與報表中心兩處
5. 交付時，將尚未歸戶的轉帳記錄一併掛到該張簽收單
6. 既有簽收單依付款日期一次性回填
7. 簽收單新增「轉帳明細（非現金）」區塊，有自己的小計
8. 轉帳金額不計入交付總金額，摘要區另加一行標示
9. 付款方式為轉帳的記錄，狀態一律顯示「已轉帳」
10. 臨時收費 `adhocPayments` 全部比照辦理
11. 報表中心收款明細一併納入臨時收費，依收款日期對應期別

## 4. 更正付款方式

### 判斷可否更正

以 `handoverId` 是否為 `NULL` 作為唯一判準，比 `handoverStatus` 準確（歸戶後的轉帳 `handoverStatus` 仍是 `pending`，但同樣必須鎖住）：

- `handoverId IS NULL` → 可更正
- `handoverId` 有值 → 鎖住

### 手持現金的連動

不需要補帳邏輯。[`/api/cash/balance`](../../src/app/api/cash/balance/route.ts) 是即時 SUM 查詢，更正後自動反映：現金改轉帳則餘額減少，轉帳改現金則餘額增加。

## 6. 資料流程

```
收款（現金）──┐
              ├─→ handoverStatus=pending ──→ 交付時 ──→ handoverStatus=handed_over
臨時收費現金──┘        ↑                                  handoverId=該單
                       │
                  計入手持現金
                  （balance API）

收款（轉帳）──┐
              ├─→ handoverStatus=pending ──→ 交付時 ──→ handoverId=該單
臨時收費轉帳──┘   handoverId=NULL                        handoverStatus 不變
                       ↑                                  （僅歸戶，非交付）
                  不計入手持現金
```

**關鍵**：轉帳只綁 `handoverId`，不改 `handoverStatus`。狀態文字由付款方式決定，不由 `handoverStatus` 決定。

## 8. 實作邏輯

### 狀態文字 helper

```ts
// 轉帳的錢直接進帳戶，沒有「交付給主管」這件事
export function paymentStatusLabel(paymentMethod: string, handoverStatus: string) {
  if (paymentMethod === "transfer") return "已轉帳"
  return handoverStatus === "handed_over" ? "已交付" : "待交付"
}
```

### 簽收單明細拆組（避免污染）

歸戶後轉帳也帶有 `handoverId`，若不加付款方式條件，會混進收款明細使合計對不上：

```ts
// 現金明細
.where(and(eq(payments.handoverId, id), eq(payments.paymentMethod, "cash")))
// 轉帳明細
.where(and(eq(payments.handoverId, id), eq(payments.paymentMethod, "transfer")))
```

### 交付時歸戶轉帳

於現有兩個 UPDATE 之後追加，只綁 `handoverId`：

```ts
await db.update(payments)
  .set({ handoverId: handover.id })
  .where(and(eq(payments.paymentMethod, "transfer"), isNull(payments.handoverId)))
  .run()
```

### 臨時收費期別對應

```ts
// 收款日 2026-08-19 → 民國 115 年 8 月 → 115年7-8期
const d = new Date(paymentDate)
const rocYear = d.getFullYear() - 1911
const m = d.getMonth() + 1
const startMonth = m % 2 === 0 ? m - 1 : m
```

與 [date-utils.ts](../../src/lib/date-utils.ts) 的 `getCurrentPeriod()` 同一套邏輯。

### 既有 PUT 端點

[`api/payments/[id]/route.ts`](../../src/app/api/payments/[id]/route.ts) 的 PUT 直接展開 request body 寫入，`handoverId`、`handoverStatus` 都可被外部覆寫。更正功能不走這支；該端點目前無 UI 使用，是否一併收斂留待實作時評估。
